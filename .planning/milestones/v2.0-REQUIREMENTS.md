## v2 Requirements (current milestone)

### CFG — Sensor configuration (Plugin UI ↔ device)

- [x] **CFG-01**: Firmware parses Red Pitaya–style **`CFG:`** commands (minimum: accel/gyro full-scale or sensitivity presets for single ICM) and applies to ICM20948 registers
- [x] **CFG-02**: Plugin ESP32 branch forwards **`CFG:`** / sensor preset UI actions to TCP command socket (not RP-only code path)
- [x] **CFG-03**: Operator can change a documented preset (e.g. ±2g/±250°/s vs ±4g/±500°/s) and see scaled values change in Open Ephys without reflash
- [x] **CFG-04**: `SENSORS:` line reflects active sensor id/name after config change (or documented fixed map)

### RATE — Sample rate

- [x] **RATE-01**: Firmware accepts **`FREQ:`** (or `FREQ `) command and changes `SAMPLE_HZ` loop timing within allowed range (default 100, min/max documented)
- [x] **RATE-02**: Plugin sample-rate editor on ESP32 node either **controls** firmware rate or is **disabled with “100 Hz fixed”** label—no silent no-op (addresses MD-04 in plugin review)
- [x] **RATE-03**: Handshake / status text reports actual `sample_rate=` matching firmware

### FUSION — Orientation / quaternion filter

- [x] **FUSION-01**: Implement orientation filter (Madgwick, Mahony, or ICM DMP) producing unit quaternion **q = (w,x,y,z)** from gyro+accel (+ mag optional)
- [x] **FUSION-02**: Firmware accepts **`FILTER:`** command (or documented subset) to enable/disable or select filter mode—parity with RP command surface where Plugin sends it
- [x] **FUSION-03**: Quaternion samples exposed on the wire: either **extend channel map** (documented) or **fixed slots** (e.g. ch7 + expanded payload / second packet type—design locked in Phase 2 plan)
- [ ] **FUSION-04**: Filter runs at acquisition sample rate without >5% frame drops over 60 s on USB and Wi-Fi TCP

### OSIM — OpenSim movement

- [ ] **OSIM-01**: Plugin ESP32 acquisition path invokes **quaternion OpenSim UDP v2** forwarding (extend `sendOpenSimQuaternionPacket()` for ESP32 branch) **or** documented equivalent host bridge
- [ ] **OSIM-02**: `ephys_to_opensim_bridge.py` / `opensim_live_realtime.py` consume quaternion stream (not raw int16 accel-only) with ESP32 channel map doc
- [ ] **OSIM-03**: End-to-end test: Plugin acquire → OpenSim live/visualizer shows **non-trivial orientation** (not identity/frozen) during known motion
- [ ] **OSIM-04**: Runbook updated in `docs/open-ephys-plugin.md` and `.planning/PLUGIN-INTEGRATION.md` with quaternion layout + env vars

### HOST / DOCS

- [ ] **HOST-04**: `host/esp32_tcp_client.py` optional decode of quaternion channels for bench verification
- [ ] **HOST-05**: Command matrix table (REDPITAYA, START, FREQ, FILTER, CFG) in `docs/arduino-ide-guide.md`
